# Backend / science / frontend integration

## Shared API contract

`contracts/openapi.yaml` is generated by `backend/export_openapi.py` from FastAPI/Pydantic. `/openapi.json` and `/docs` expose the same running contract. Regenerate after changing public models/routes. Frontend can generate TypeScript without editing this backend:

```powershell
# From frontend, after installing openapi-typescript as a development dependency:
npx.cmd openapi-typescript ../contracts/openapi.yaml -o src/api/schema.d.ts
```

Use `http://127.0.0.1:8000/api/v1` for the documented local run command. The frontend now has generated types, real queries and live data views; Vite proxies same-origin `/api` to this server. For separate-origin deployments configure `VITE_API_BASE_URL` to the complete API prefix and allow the frontend origin in `CLIMATELENS_CORS_ORIGINS`. See `../frontend/README.md`.

Success observations: `{status: 'ok', data, meta}`. Valid unmatched observations: `status: 'no_data'`, empty array (or empty page items). Comparison no-data has `data: null`. `meta.observation_count` counts returned observations, not total disasters; paginated `data.total` is matching available records. An offset beyond the collection returns an empty page, not measured zero. Filtered `meta.period` covers returned source labels; empty results have null period bounds. Event records without timestamps keep available years only. Metadata has source IDs, declared units/geographical/temporal level, method and limitations. Missing dependency is HTTP 503 `{error:{code,message,details}}`, not `no_data`.

Record IDs are opaque strings. Join rainfall and boundary properties through verified `state_id` only, never name guesses. Boundary coordinates are longitude/latitude in EPSG:4326; the preparation CLI reprojects official NWIC EPSG:7755 geometry with pyproj and preserves islands/holes. Rainfall returns values without geometry. Select an actual `capabilities.rainfall_observation_dates` using `observation_date`; ambiguous multi-date state/year requests return `OBSERVATION_DATE_REQUIRED`, not an inferred annual total. Current rainfall unit is null because the workbook does not declare it. No-data styling must differ from measured zero. Drought remains national, temperature regional/monthly; basin cyclone coverage is not Indian landfall.

## Prepared-storage contract (new backend convention)

No processed files were supplied initially. Manual preparation CLIs normalize supported workbook source fields and separately reproject official NWIC geometry. Provenance/omission reports accompany observations. Additional science-team exports may follow this storage contract. Undefined drought columns, incompatible temperature data and annual rainfall metrics remain unsupported; raw column positions are not guessed.

`manifest.json` structure:

- `version`: integer `1`.
- `processed_at`: actual processing timestamp string.
- `metadata`: catalog `Metadata` object (not a climate metric copied from one dataset).
- `sources`: `Source[]` with unique actual IDs and provider/source URL/provenance details.
- `capabilities`: declared supported controls; `comparison_metrics` is the list of science-validated metric IDs. Other capability keys may convey supported years/regions/coverage; frontend must not infer scientific validity from file existence.
- `datasets`: object keyed by the dataset names below. Each value has `path`, `format`, `meta`.

`Metadata` fields: `metric`, nullable `unit`, `geographic_level`, `time_resolution`, `period:{start,end}` (nullable strings), `source_ids`, nullable `method`, nonnegative `observation_count`, `limitations`. These are actual declared source/calculation facts, not arbitrary presentation values. Every source ID must exist in the catalog.

`Source` fields: `id`, `name`, `provider`, nullable absolute HTTP(S) `url`, `geographic_coverage`, `temporal_coverage`, `data_format`, `purpose`, `provenance_status`, `limitations`.

Dataset paths must be relative and confined inside the prepared-data root; absolute/traversal paths and symlink escapes are rejected. Formats: `parquet` (`.parquet`), `json` (`.json`) and `geojson` (`.geojson`). JSON record datasets are bare arrays; boundaries are a FeatureCollection. No public file path is accepted in API queries. Missing/invalid files are explicit errors, and the cache is invalidated by file signature changes. Prepared tables are loaded and validated on first use and cached; for very large archives partition/export appropriate demo datasets rather than relying on this cache as a full database engine.

Required row schemas (extra fields rejected; event attributes belong in `attributes`):

| Dataset | Record fields / scope |
| --- | --- |
| `states` | `state_id`, `name`; state-level geographic catalog |
| `boundaries` | FeatureCollection of Polygon/MultiPolygon; each feature has `properties.state_id`, `properties.name` matching states; closed valid-range rings |
| `rainfall` | `state_id`, `year`, nullable ISO `date`, `value`; daily records preserve dates, annual records require explicit compatible metadata |
| `drought` | `year`, `value`; `meta.geographic_level = national` |
| `temperature` | `region`, `year`, nullable `month`, `value`; `meta.geographic_level = regional` |
| `floods`, `landslides` | `event_id`, nullable `state_id`, nullable `year`, nullable `timestamp`, nullable coordinate pair `longitude`/`latitude`, `attributes` object |
| `cyclones` | `storm_id`, `name`, `year` |
| `tracks` | `storm_id`, timezone-aware source `timestamp`, `longitude`, `latitude`, nullable `wind`, `pressure`, `wind_unit`, `pressure_unit` |

Source intensity measurements require their source units. Event years and timestamps must agree. Preserve unavailable dates/coordinates as null; do not synthesize them. All numeric measurements must be finite. Do not use a state's source absence as an observed zero.

## Analytics plugin protocol (not an upstream NIElytics signature)

The included default `app.services.nielytics_adapter` calls actual pinned NIElytics 0.2.0.dev1 APIs. A custom science adapter selected by `CLIMATELENS_ANALYTICS_MODULE` must expose:

```python
def analyze(*, operation: str, parameters: dict, repository):
    # Call the actual NIElytics/data-team implementation here.
    # Return the documented Envelope-compatible structured result.
    ...
```

This protocol is a ClimateLens boundary, not an upstream NIElytics signature. The delivered adapter invokes actual summaries, Mann–Kendall, event aggregation, InsightEngine and regional catalog overlap. Current daily rainfall cannot satisfy annual-rainfall preconditions; supported event insights remain available with that limitation. Imports use trusted local configuration, never user query parameters. No synthetic fallback or external LLM is used.

Operations:

- `compare`: parameters `state_a`, `state_b`, `metric`, `start_year`, `end_year`. Allowed candidate metrics: `rainfall_annual_total`, `rainfall_anomaly`, `flood_event_count`, `landslide_event_count`; only manifest-declared supported metrics are enabled. The plugin must enforce same definitions/units/resolution/common observation periods, sufficient coverage and valid missing-data handling. Backend validates returned identity/metric/period and result structure; it cannot certify the unseen scientific implementation.
- `insights`: `state_id`, optional paired `start_year`/`end_year`. Deterministic facts/explanations must come from actual NIElytics executions. No external LLM is used.
- `multi_hazard`: same filters; return validated relationships with individual records/sources and explicit noncausal limitations. Do not infer causation from overlap.

Exact output models are in `app/services/analytics_models.py` and OpenAPI. `Insight.period` is its time period and `Insight.method` is its methodology; computed value, unit, geographic resolution, observations and sources must reflect actual calculations. Comparison values and differences are supplied by the plugin, never calculated in routes. Null percentage is required when its declared baseline is zero. A plugin producing invalid/unprovenanceable data fails explicitly, never degrades to fabricated values. Empty valid analytics uses documented `no_data` with an explanation in limitations.

## Reporting and judging

Reports render supported prepared rainfall/event rows and available verified insight output, not newly calculated summaries. Source definitions/methods/limitations and generation date accompany observations. No reportable records means `REPORT_UNAVAILABLE`, never a generic blank PDF. Browser clients must check HTTP success and PDF content type before saving.

Use `/metadata` for actual dates/years and `/sources` for lineage. Supported workbook events, tracks and daily rainfall have omission evidence; official geometry is prepared separately. The frontend now consumes this contract. Annual comparisons, national drought percentages and regional temperature still require additional compatible data. Backend HTTP/PDF smoke outcomes are in `VERIFICATION.md`; connected-browser outcomes belong in the frontend verification record, not synthetic test claims.
